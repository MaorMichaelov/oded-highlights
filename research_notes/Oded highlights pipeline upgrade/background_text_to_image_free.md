## 1. Cloudflare Workers AI text-to-image (best "free, scriptable, works from GitHub Actions" candidate)

### Takeaway
Workers AI gives every Cloudflare account (no card) 10,000 Neurons/day free, reset 00:00 UTC; that is roughly 100+ native-1280x720 images/day with FLUX.2 klein 4B or roughly 170-230 square images/day with FLUX.1 schnell, so 16-30 plates fit in one day. Use `flux-2-klein-4b` (accepts width/height up to 1920) for native 16:9; `flux-1-schnell` has NO width/height parameter in its documented schema; SDXL/SDXL-Lightning/DreamShaper are scheduled for deprecation on 2026-11-20 (6 days from today), so do not build on them.

### Cited Findings
- Free allocation: 10,000 Neurons per day at no charge on Workers Free; above that you need Workers Paid ($0.011 per 1,000 Neurons); limits reset daily 00:00 UTC; "If you exceed any one of the above limits, further operations will fail with an error" (i.e. free plan hard-stops, no surprise bill). **[DOC]** — [CF pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) (fetched by curl)
- flux-1-schnell price: $0.0000528 per 512x512 tile + $0.0001056 per step = 4.80 neurons per 512x512 tile + 9.60 neurons per step. **[DOC]** — [CF pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)
- flux-2-klein-4b price: 5.37 neurons per input 512x512 tile, 26.05 neurons per output 512x512 tile. flux-2-klein-9b: 1363.64 neurons per first MP (1024x1024) + 181.82 per subsequent MP (about 7 images/day free). flux-2-dev: 18.75/input tile/step, 37.50/output tile/step. lucid-origin (Leonardo): 636 neurons per 512x512 tile + 12/step (very costly, a 1280x720 would be about 2,200+ neurons so ~4 images/day). phoenix-1.0: 530/tile + 10/step. **[DOC]** — [CF pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)
- stable-diffusion-xl-base-1.0 (Beta), stable-diffusion-xl-lightning (Beta) and dreamshaper-8-lcm all carry "Planned Deprecation 11/20/2026"; SDXL pages show "Unit Pricing $0.00 per step" (free beta). **[DOC]** — [SDXL base](https://developers.cloudflare.com/workers-ai/models/stable-diffusion-xl-base-1.0/index.md), [Lightning](https://developers.cloudflare.com/workers-ai/models/stable-diffusion-xl-lightning/index.md), [DreamShaper](https://developers.cloudflare.com/workers-ai/models/dreamshaper-8-lcm/index.md)
- SDXL/Lightning/DreamShaper input: `prompt` (req), `negative_prompt`, `width`/`height` 256-2048, `num_steps` (default 20, max 20), `guidance` (default 7.5), `seed`; output is a binary image stream (PNG) — "The binding returns a ReadableStream". **[DOC]** — pages above. (I could not confirm in this session that the REST path returns raw bytes rather than JSON for these; the older CF tutorials say it returns raw PNG bytes — **[CLAIMED]**, from memory.)
- flux-1-schnell schema (authoritative JSON from the docs repo): input only `prompt` (1-2048 chars), `steps` (max 8, default 4), `additionalProperties: false`; model page example also passes `seed`. Output `{"image": "<base64>"}` (docs example builds a `data:image/jpeg` URI, so JPEG). No width/height. **[DOC]** — [schema JSON in cloudflare-docs](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/workers-ai-models/flux-1-schnell.json), [model page](https://developers.cloudflare.com/workers-ai/models/flux-1-schnell/index.md)
- A community report says adding width/height to flux-1-schnell used to work then returned HTTP 500; the output resolution of schnell is not documented (commonly 1024x1024 but unconfirmed). **[CLAIMED]** — [Answer Overflow thread](https://www.answeroverflow.com/m/1311727991209984060)
- flux-2-klein-4b: Black Forest Labs partner model, "fixed 4-step inference", multipart/form-data input even for text-only; params: `prompt` (req), `width` (default 1024, range 256-1920), `height` (default 768, range 256-1920), `seed`, `guidance` (float), optional `input_image_0..3` (each < 512x512). Official REST example:
  `curl --request POST --url 'https://api.cloudflare.com/client/v4/accounts/{ACCOUNT}/ai/run/@cf/black-forest-labs/flux-2-klein-4b' --header 'Authorization: Bearer {TOKEN}' --header 'Content-Type: multipart/form-data' --form 'prompt=a sunset at the alps' --form width=1024 --form height=1024`. Output `{"image": "<base64>"}`. **[DOC]** — [CF changelog 2026-01-15](https://developers.cloudflare.com/changelog/post/2026-01-15-flux-2-klein-4b-workers-ai/index.md)

- Token: dashboard → Workers AI → "Use REST API" → "Create a Workers AI API Token" (needs Workers AI Read+Edit); also copy Account ID. - Third-party calculator figure 43.20 neurons for a 512x512 4-step schnell image (matches 4.80 + 4x9.60). **[CLAIMED]** — [Cloudflare pricing summary in search results](https://developers.cloudflare.com:8443/workers-ai/platform/pricing)

### Cost arithmetic (my calculation from the DOC prices; no image was billed)
- schnell 4 steps, one 1024x1024 image: 4 tiles x 4.8 + 4 steps x 9.6 = 57.6 neurons if step price is flat per step (=> ~173 images/day) or up to ~192 (if per-step cost also scales with tiles) (=> ~52/day worst case). Either way 16-30 plates/day fit.
- klein-4b 1280x720 (3.52 tiles) text-only: 3.52 x 26.05 ≈ 92 neurons => ~108 images/day. 1920x1080 (7.9 tiles) ≈ 206 neurons => ~48/day.

### Ready-to-run script (UNTESTED: compiles, never called the API)
```python
# cf_plates.py   pip install requests pillow
import os, sys, base64, io, requests
from PIL import Image
ACC=os.environ["CLOUDFLARE_ACCOUNT_ID"]; TOK=os.environ["CLOUDFLARE_API_TOKEN"]
BASE=f"https://api.cloudflare.com/client/v4/accounts/{ACC}/ai/run/"
H={"Authorization":f"Bearer {TOK}"}
def klein(prompt, w=1280, h=720, seed=1):           # native 16:9, multipart
    r=requests.post(BASE+"@cf/black-forest-labs/flux-2-klein-4b",headers=H,
        files={"prompt":(None,prompt),"width":(None,str(w)),"height":(None,str(h)),"seed":(None,str(seed))},timeout=120)
    r.raise_for_status(); return r.json()["result"]["image"]
def schnell(prompt, seed=1, steps=4):               # JSON; NO width/height -> crop to 16:9 afterwards
    r=requests.post(BASE+"@cf/black-forest-labs/flux-1-schnell",headers=H,
        json={"prompt":prompt,"steps":steps,"seed":seed},timeout=120)
    r.raise_for_status(); return r.json()["result"]["image"]
if __name__=="__main__":
    p=sys.argv[1]; fn=klein if (len(sys.argv)<3 or sys.argv[2]=="klein") else schnell
    im=Image.open(io.BytesIO(base64.b64decode(fn(p)))); print(im.size); im.save("plate.png")
```
curl equivalent for schnell: `curl -s https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/run/@cf/black-forest-labs/flux-1-schnell -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" -d '{"prompt":"...","steps":4,"seed":7}' | jq -r .result.image | base64 -d > out.jpg`.
GitHub Actions: store `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN` as repo secrets, run once, commit/cache the PNGs (actions/cache or an artifact). Add a 1-2 s sleep and retry-on-5xx; seeds make plates reproducible.

### Inferences
- Rank 1 for this pipeline: klein-4b at 1280x720 (native 16:9, Apache-2.0, ~100/day). Fallback: schnell at square then crop (crop 1024x1024 → 1024x576 discards 44% of the height, so put the subject detail in the middle band of the prompt and use "wide cinematic" wording), or schnell plus outpainting is not worthwhile.
- Possible gotcha: klein dimension granularity (probably multiples of 16) is not documented; 1280x720 is divisible by 16 (720 = 45x16) so it should be fine, but I did not verify. If a 400 appears, try 1280x704.
- Because the three SD-family models are being removed on 2026-11-20, avoid them; DreamShaper/SDXL-Lightning would be the only ones with `negative_prompt`. FLUX models take no negative prompt, so phrase exclusions positively ("empty room, unoccupied").

### Gaps
- Not tested with a real token. Actual output size of flux-1-schnell and klein quality unverified here.
- Whether the free plan serves partner models (klein, lucid) without a paid billing method: the pricing page notes that some models "require a paid billing method" and lists specific Kimi/GLM ids; the visible list I read did not include klein-4b or flux-1-schnell, but the list was truncated in my extraction. Check the note on the pricing page.

## 5. Local CPU generation in GitHub Actions (stable-diffusion.cpp)

### Takeaway
Feasible but slow: FLUX.2-klein-4B Q4 GGUF (2.5 GB + Qwen3-4B Q4 2.4 GB text encoder + 0.34 GB VAE, ~5.5 GB RAM) or Z-Image-Turbo Q4 (3.7 GB) can produce 1024x576 on a 4-vCPU runner, but I found NO published CPU timing for these in sd.cpp; my estimate is minutes per image (roughly 2-10 min at 4 steps; ~30-45 s for SD-Turbo-class at 512). SD-Turbo/SDXL-Turbo are fast but their licences are not commercial-friendly. I did not run anything (shared machine OOM constraint).

## 7. Post-processing for fit under a cut-out portrait

### Takeaway
Tested Pillow/numpy function below (ran in 0.16 s on a synthetic image): crop to 16:9, Lanczos resize, unsharp, left-weighted blur and darkening via smoothstep gradient, vignette, warm tint, slight desaturation and contrast. It worked on synthetic data only, not on real plates.

### Cited Findings
- **[TESTED]** (my code, executed here):
```python
import numpy as np
from PIL import Image, ImageFilter, ImageEnhance
def fit_16x9(im, W=1280, H=720):
    w, h = im.size; tr = W/H
    if w/h > tr: nw=int(h*tr); im=im.crop(((w-nw)//2,0,(w-nw)//2+nw,h))
    else:        nh=int(w/tr); im=im.crop((0,(h-nh)//2,w,(h-nh)//2+nh))
    return im.resize((W,H), Image.LANCZOS)
def smooth(t): return t*t*(3-2*t)
def make_plate(im, W=1280, H=720, left_dark=0.55, left_span=0.50, blur=1.2, vignette=0.35,
               saturation=0.92, contrast=1.06, sharpen=True, tint=(1.0,0.97,0.93)):
    im = fit_16x9(im.convert("RGB"), W, H)
    if sharpen: im = im.filter(ImageFilter.UnsharpMask(radius=1.6, percent=70, threshold=3))
    b = im.filter(ImageFilter.GaussianBlur(blur*2.0))
    x = np.linspace(0,1,W,dtype=np.float32)[None,:]; yv = np.linspace(0,1,H,dtype=np.float32)[:,None]
    wl = 1 - smooth(np.clip(x/left_span,0,1))                    # 1 at left edge -> 0 at 50% width
    a = np.asarray(im,np.float32); bb = np.asarray(b,np.float32)
    a = a*(1-0.6*wl[...,None]) + bb*(0.6*wl[...,None])           # blur left more
    a *= (1-left_dark*wl)[...,None]                              # darken left
    r = np.sqrt(((x-0.5)/0.5)**2 + ((yv-0.5)/0.5)**2)/np.sqrt(2)
    a *= (1-vignette*smooth(np.clip(r,0,1)))[...,None]           # vignette
    a *= np.array(tint,np.float32)
    out = Image.fromarray(np.clip(a,0,255).astype(np.uint8))
    out = ImageEnhance.Color(out).enhance(saturation); return ImageEnhance.Contrast(out).enhance(contrast)
```
  Result on synthetic noise image: mean luma 37 (left 10%), 108 (centre), 86 (right 10%).

### Recommended parameter ranges (my judgement, untested on real plates)
- Left darkening 0.45-0.65 (0.55 default) over the left 50% with smoothstep falloff so no hard edge shows behind the portrait cut-out; keep right side untouched so details survive.
- Blur: 1.0-2.0 px at 1280 wide on the left (portrait edge halo hides blur mismatches); keep right at original sharpness. Scale radii x1.5 when working at 1920 wide.
- Vignette 0.25-0.40; saturation 0.88-0.95 (thumbnails look cleaner slightly desaturated before the portrait is popped); contrast 1.05-1.10; warm tint (1.0, 0.97, 0.93) for lawyer/airport plates, cool tint (0.94, 0.98, 1.04) for police/night plates.
- Final output: 1280x720 JPEG q90 for YouTube (limit 2 MB) or build at 1920x1080 and downscale at export; add a 3-6% gaussian grain after downscale if the AI look is too smooth.
- Add a very light darkened band (10-15%) at the bottom 15% if the YouTube duration badge overlaps.

### Inferences
- Gradient+blur on the left also hides AI texture artefacts and makes any text-like gibberish unreadable.

### Gaps
- Parameters not validated against real model output or the actual portrait cut-out.
